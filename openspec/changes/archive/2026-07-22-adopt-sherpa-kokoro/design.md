## Context

AudiobookMaker 当前以 `TTSRuntimeClient` 隔离语音实现，生产路径是 `AVSpeechSynthesizer`，模型列表、设置和持久化中另有一个不可用的 CosyVoice/MLX 占位。该占位只面向 Apple Silicon，且 App 目前没有第三方运行时依赖、模型下载器或网络客户端权限。

本变更需要同时覆盖 Intel x86_64 与 Apple Silicon arm64，维持书籍转换完全离线，并避免将数百 MB 的模型权重放入 App 安装包。Kokoro 音色选择必须贯穿设置、任务快照、恢复和合成请求，试听则不能污染正式转换队列。

## Goals / Non-Goals

**Goals:**

- 使用一个通用的 sherpa-onnx/Kokoro 运行时覆盖 Intel 与 Apple 芯片。
- 将 Kokoro 权重作为安装后的可选下载，提供可恢复、可校验、原子提交的安装流程。
- 在“模型”菜单中完成下载、默认模型切换、音色选择和试听。
- 新任务固定模型 ID、模型版本和音色 ID，保证一本书恢复前后声音一致。
- 删除 CosyVoice/MLX 的产品入口、持久化种子和相关文案。
- 保持书籍正文、参考数据和生成音频只在本机处理。

**Non-Goals:**

- 不支持加载任意 ONNX TTS 文件或用户自定义模型仓库。
- 不提供零样本音色克隆、情绪提示、音高编辑或音色混合。
- 不在本期加入后台自动更新、差分更新或多个 Kokoro 精度变体。
- 不自动替用户下载模型，也不在安装 Kokoro 后自动改变正在运行或已有的任务。

## Decisions

### 1. 运行时使用 sherpa-onnx，首个外置包固定为 Kokoro 多语言 v1.1 INT8

首版目录使用内部稳定 ID `sherpa-onnx/kokoro-multi-lang-v1_1-int8`，显示名为“Kokoro 多语言 v1.1”，来源固定到经审核的 sherpa-onnx TTS release。包内包含 INT8 ONNX 权重、`voices.bin`、token、词典、文本规范化 FST、eSpeak NG 数据和许可文件。

选择 INT8 是为了降低下载、磁盘和 Intel CPU 内存压力；完整精度版本留作后续听感基准的候选。选择 sherpa-onnx 官方适配包而不是直接下载原始 Kokoro ONNX，是因为运行还依赖与该权重匹配的音色、词典和规范化资源。

替代方案是官方 PyTorch CosyVoice3、MLX 或 `cosyvoice.cpp`。它们分别存在 Intel 发行中断、仅 Apple Silicon 或社区运行时成熟度风险，不作为首版产品路径。

### 2. sherpa-onnx 二进制随 App，模型权重不随 App

将 sherpa-onnx、ONNX Runtime、C/Swift 桥接和许可声明构建为同时包含 x86_64、arm64 slice 的签名 XCFramework，并由独立语音服务链接。App bundle 不包含 Kokoro 权重，也不在首次启动静默下载。

运行时二进制是 App 功能代码，随版本签名和公证；模型属于可替换数据，保存到共享 Application Support 的版本目录。这样可保持 App 下载体积可控，同时避免执行下载代码带来的签名风险。

### 3. 使用版本化清单驱动安全下载

App 内置小型 `ModelManifest`，至少包含模型 ID、显示名、版本、HTTPS URL、压缩包大小、安装后大小、SHA-256、包结构版本、运行时最低版本、音色清单版本和许可元数据。下载采用 `URLSessionDownloadTask`，写入模型根目录的 staging 区；支持取消和系统允许的断点续传。

状态机为：

```text
notInstalled → downloading → verifying → installing → installed
                    │              │           │
                    └──────────────┴───────────┴→ failed → retry
```

只有下载完整、SHA-256 匹配、解包路径安全、必需文件齐全且运行时探测成功后，才通过同卷原子 rename 提交到 `<model-id>/<version>/`。旧 staging 和无效 resume data 可以清理，已提交版本不得被失败安装覆盖。

不选择在模型目录中执行脚本，也不信任压缩包提供的绝对路径、符号链接或未列入清单的可执行文件。

### 4. 模型菜单是安装与音色管理的唯一主入口

Sidebar 的“模型”项保留。内容列始终展示 Apple 系统语音与 Kokoro；Kokoro 未安装时展示预计下载大小和“下载”，下载中展示确定或不确定进度以及取消/重试。只有 `installed + runtime ready` 才允许设为默认和试听。

详情列展示框架、模型版本、支持语言、安装位置占用、许可、运行状态和音色 Picker。音色条目由运行时/受信清单提供稳定 `voiceID`、显示名、语言提示等元数据；持久化选择以 model ID 为命名空间，避免不同模型的音色 ID 冲突。

设置窗口的默认模型 Picker 复用同一模型目录状态，不复制静态列表。未安装的 Kokoro 可被看见，但不可成为默认模型。

### 5. 试听走独立、可抢占的请求通道

试听使用固定且本地化的短文本，或者当前所选语言对应的内置样句；不读取书籍正文。每次只允许一个试听请求，新试听先取消旧试听。试听音频写入可清理缓存并直接播放，不创建 ConversionJob、章节 checkpoint 或导出产物。

试听请求与正式合成共用模型加载和音频校验，但具有独立 request purpose、较短超时和最高单次文本长度。正式转换运行时，试听必须遵从运行时并发能力；首版建议禁止试听并说明原因，以免改变长任务时延和内存峰值。

### 6. 模型与音色在任务创建时冻结

`SynthesisRequest`、ConversionJob 和 checkpoint 增加 `modelID`、`modelVersion`、`voiceID`。默认模型/音色的变更只影响之后创建的任务。恢复任务时必须验证完全相同的三元组仍可用；版本缺失或音色不存在时暂停恢复并引导用户重新安装相同版本，禁止静默换音色。

Apple 系统语音也使用稳定的 voice identifier 进入同一契约，从而保持业务层不针对框架分支。

### 7. 下载联网与内容数据通道隔离

开启 App Sandbox 网络客户端权限只供模型包管理器访问清单允许的 HTTPS 来源。下载请求不得携带书籍、章节、文件名、作者、音色选择或稳定用户标识；合成运行时不具备网络 API，且模型安装完成后断网仍能转换和试听。

## Risks / Trade-offs

- [Kokoro 中文长文本可能出现发音或韵律问题] → 沿用按标点安全切片，增加数字、日期、中英混排和专名回归样本，并在发布前用真实 EPUB 做听感验收。
- [INT8 可能降低音质] → 与未量化参考输出做盲听和音频有效性对比；若不达标，通过新模型版本引入完整精度包，而不改变运行时 API。
- [模型源在部分网络环境不可达] → 提供明确错误、断点续传和重试；清单允许未来切换到自有 HTTPS 分发，但所有镜像必须使用同一哈希。
- [第三方动态库增加签名、公证和崩溃面] → 固定源码提交和 ONNX Runtime 版本，生成 SBOM/Notice，在 x86_64 与 arm64 分别进行签名、公证、冷启动和压力测试。
- [103 个音色列表难以选择] → 提供搜索、语言/性别元数据显示和单击试听，保存每个模型最近一次音色。
- [试听与转换争用 CPU/内存] → 使用独立可取消请求并服从运行时并发上限；首版在转换活跃时禁用试听。
- [模型更新导致恢复任务声音变化] → checkpoint 固定模型版本和 voice ID，保留被未完成任务引用的版本，禁止自动就地替换。

## Migration Plan

1. 引入新的稳定模型/音色标识和数据迁移：CosyVoice 默认值迁移为 Apple 系统语音；删除 CosyVoice 目录种子但不改写进行中任务历史。
2. 集成通用 sherpa-onnx 语音服务和 Kokoro 测试夹具，在两种架构完成固定文本合成验证。
3. 上线模型清单、下载、校验和原子安装，再接入模型目录状态。
4. 上线音色选择、试听以及任务三元组锁定与恢复校验。
5. 删除 CosyVoice UI、文案、依赖假设和测试，更新分发/许可文档。
6. 发布前验证“仅 Apple 系统语音”的无模型升级路径、首次下载、断网运行、下载失败恢复和双架构真实 EPUB 转换。

回滚时可以隐藏 Kokoro 清单并恢复 Apple 系统语音为唯一可创建新任务的模型；已下载数据保留为不可执行的数据，避免回滚版本误删用户正在使用的模型资源。

## Open Questions

- 发布前需要以真实中文 EPUB 冻结默认音色和试听样句；这不影响模型/音色选择契约。
- 是否提供完整精度 Kokoro 作为“高品质”变体，取决于 INT8 在 Intel 与 Apple Silicon 上的音质、RTF 和内存验收结果，不纳入本变更首版。
